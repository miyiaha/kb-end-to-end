# 知识类型词表与企业受控标签词表（参考）

> `kb-end-to-end` 的受控词表。type 必须取自下表，不得自造；L2–L4 为治理用受控词表，可随企业组织按年更新。个人/通用域允许 `department: 个人/通用` 或留空。

## 一、知识类型词表（type，固定枚举 7 类）

| type 值 | 含义 | 示例 |
|---------|------|------|
| `concept` 概念定义 | 术语、原理、定义 | 卡拉杰克矩阵、微服务 |
| `method` 方法论 | 可复用的方法/流程 | 供应商评估、RACI 配置 |
| `solution` 方案文档 | 具体方案/报告/决策 | 厂区供应链方案 |
| `template` 模板 | 可复制复用的模板 | 会议纪要、合同模板 |
| `case` 案例 | 真实案例/复盘 | 缺货应急、故障复盘 |
| `data` 数据资料 | 报表、清单、对照表 | 供应商名录、价格基线 |
| `note` 碎片笔记 | 临时/未完成沉淀 | 读书摘抄、会议速记 |

> `note` 类准入细则：须含 ≥1 个可操作步骤，或被 ≥1 篇其他笔记 `[[双链]]` 引用，方准入。

> **结构索引（MOC 总索引）特别说明**：MOC 是仓库的「地图/首页」，**不是知识类型**，不计入 7 类知识类型统计。MOC 笔记统一用：
> - `type: solution`（本质是一份目录型方案文档）+ `category: 索引`
> - 或在 frontmatter 显式标注 `is_index: true`，下游治理统计时剔除。
> 禁止将 `MOC` 当作 type 枚举值（会破坏 7 类受控统计）。

### 有效期策略（valid_until）
| type | 有效期约定 | 复审触发 |
|------|-----------|----------|
| method / template | 默认长期有效，写 `valid_until: 长期` | 年度复审 / 关联标准变更 |
| solution | 跟随项目周期，写项目结项日或 `长期` | 项目里程碑 |
| data（合规/法规） | 跟随法规失效日（如国标换版） | 法规更新预警 |
| concept / case / note | 写 `长期` 或具体日期 | 内容过时即归档 |

## 二、企业受控标签词表（分层）

| 层级 | 维度 | 说明 | 维护方式 |
|------|------|------|----------|
| L1 | 知识类型 | 固定 7 类枚举（见上方） | 不可自定义 |
| L2 | 业务域 | 按组织实际业务线划分 | 年度评审更新 |
| L3 | 产出部门 | 对齐组织架构 | 新增/撤销部门时同步 |
| L4 | 密级 | 固定 4 档枚举（见下方） | 不可自定义 |

> **重要提示**：L2 和 L3 的取值因组织而异，下方仅提供示例值和行业模板。实际使用时必须根据用户所在组织定制，不能直接套用示例值。L1 和 L4 为固定枚举，可直接使用。

## 三、frontmatter 双层字段

| 字段 | 层 | 说明 |
|------|----|------|
| type | 基础 | §一 类型词表 |
| category | 基础 | 业务子分类 |
| source | 基础 | 内部产出/外部引入/会议沉淀/项目交付 |
| department | 治理 | L3（个人域可 个人/通用/留空） |
| project | 治理 | 关联项目名 |
| owner | 治理 | 知识责任人 |
| tags | 基础 | 自由标签（细粒度检索） |
| status | 基础 | 草稿｜定稿｜归档 |
| security_level | 治理 | L4 密级 |
| valid_until | 治理 | 有效期 YYYY-MM-DD |
| create_time | 基础 | {{date}} |

## 四、密级闸门（L4 固定枚举）

| security_level | 开放范围 | 入库要求 |
|----------------|----------|----------|
| 公开 | 全员 | 可直接入库 |
| 内部 | 企业内部 | 去标识后可入库 |
| 受限 | 指定部门/角色 | 需部门负责人审批 |
| 机密 | 极小范围 | 原则上不入通用库，走隔离区 |

> 置信度阈值（如 0.8）为示意值，需按基线校准，非既定标准。
