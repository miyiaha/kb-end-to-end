# 存量库治理与自动运营实战手册（Auto-Ops Playbook）

> 来源：2026-08-31 ~ 09-01 飞书个人云空间治理项目，全程实战验证（308 项文件全盘治理 → 48 小时转入自动运营）。
> 定位：本技能原流程面向「从零建库」；本手册把能力延伸到 **存量库**（已有几百上千个文件的盘/库），并补上「建完之后怎么自动跑起来」的运营层。适用于飞书云盘、Obsidian、企业网盘等任意载体。

---

## 1. 什么时候用本手册

- 库已存在且堆积大量文件（100 项以上），不是从零开始
- 痛点信号：根目录/顶层散落严重、没人说得清库里有什么、重复副本多、命名混乱、僵尸文件无人敢删
- 目标：从「人肉整理」切换到「自动运营」，秩序每日自愈、情报主动送达

## 2. 首轮治理四步（一次性，2~3 天）

| 步骤 | 动作 | 质量闸门 |
|------|------|---------|
| ① 全盘扫描打标 | 扫描全量文件，逐项打标 12 字段（见 §7），写索引库 | 100% 覆盖，不允许"大概扫了" |
| ② 分类归档 | 收敛 PARA 目录（00_收件箱/01_项目/02_业务领域/03_参考资料/04_归档/90_知识地图/99_回收区）；散落文件先入收件箱，逐项给归位建议，**确认后**再移动 | 根目录散落=0；误移可捞回 |
| ③ 查重与清理 | 重复组判定→保留唯一现行版；删除前**确认制+二次验证+全量备份**（manifest 审计清单） | 0 误删；删除项 100% 有备份可回溯 |
| ④ 索引落表 | 打标结果结构化写入索引库（多维表格/表格/笔记索引均可） | 索引数与实况对账吻合 |

> 实战数据（脱敏）：305 项全盘扫描、228 项根目录散落归位、46 个重复副本清零（45 项删除全备份）、二次验证拦截 3 个错移保留文件。

## 3. 自动运营引擎（4 张日程，治理完成后安装）

| 日程 | 建议时间 | 职责 | 关键规则 |
|------|---------|------|---------|
| 每日巡检 | 工作日 09:30 | 散落归集→增量入库→归位建议→音视频查重→闭环核查→报告 | 周六日与法定节假日自动跳过 |
| 行业/主题简报 | 每日 09:00 | 事件聚合→多源交叉验证→简报生成→验收入库 | 每条事件≥3 个独立来源交叉印证；低质域名黑名单 |
| 每周入库对账 | 周五 12:00 | 增量扫描入库→调用次数刷新→名称三方对齐（索引 vs 实况 vs 快照）→周简报 | 差异四分类：CONFIRM/CONFLICT/ILLEGAL/LOST |
| 月度盘点 | 每月 1 日 10:30 | 全量比对→健康分→过期预警→重复复查→结构巡检→月报 | 过期归档必须请示，归档≠删除可恢复 |
| 每周清重（v1.5） | 周五入库对账后 | 增量向量化→相似检测→D7 自动清理（巡检「自动清理清单」告知）→其余出待裁决清单 | 保护清单 D6 绝不触发；相似≠相同一律请示 |
| 月度主题总结（v1.5） | 每月最后 1 个工作日 | 按板块聚类→串起本月零散知识→点出跨资料联系→输出 HTML 报告 | 每月 1 份；产出进入⑥标准迭代 |

## 4. 四段式巡检报告（每日）

固定四段：**巡检结果 / 存在问题 / 改进措施 / 闭环状态**。
- 每个问题有台账、有期限；**3 日未闭环标红升级**
- 今日报告要核销昨日问题，闭环率是巡检的核心 KPI

## 5. 治理三规则（安全底线，人机协作）

1. **删除确认制+引用检查**：任何删除/清零/归档先请示，逐项说明依据；删除前**二次验证**（与保留项内容比对、排查错移）+ **引用检查**（全盘检查待删对象是否被白皮书/报告/网页底稿引用，被引用资产列入保护清单）+ **备份先行**（内容导出+manifest 清单）；备份审计资产（manifest、备份目录、图表目录）默认进保护清单，批量清理默认排除
2. **音视频请示制**：登记归类前先按日期+名称匹配已有转写纪要——有转写只登记互链不重复提取；无转写先请示再提取
3. **转发即入库**：转发链接=入库动作。抓正文→生成归档件→按主题路由（AI/技术→学习资源；行业/业务→参考资料；拿不准→收件箱）→登记索引→回复位置+摘要

**无人值守保护**：自动化任务遇权限失效/鉴权问题，只记录并播报请示，禁止自动发起授权流程。

### 5.1 保护机制（D6，v1.5 强制）

以下四类文件自动检测并**跳过一切清理/修改动作**（检索仍可读）：
| # | 保护规则 | 判定方式 |
|---|---------|---------|
| 1 | 01_项目 目录全部文档 | 位置前缀 |
| 2 | lifecycle=进行中项目（编制中/草稿/评审中/待发布） | 生命周期字段 |
| 3 | 公司标准文件 | [标准] 前缀 / 名称含 标准·规范·制度·规程·指引 |
| 4 | 手动标注「保护」 | 状态/备注字段人工标记 |

保护清单**绝不触发清理**，即使相似度命中重复档也只作关联标注；判定口径宁多勿少。详见 `references/knowledge-network.md` §5。

### 5.2 自动清理授权（D7，v1.5 强制边界）

**可自动处理**（无需逐条确认）：标题重复 + 内容完全一致（正文逐段比对无差异）+ 完全把握 → 保留规范正本，副本移 99_回收区 + 删索引记录（**非物理删除，可找回**），事后在巡检记录「自动清理清单」区块标识告知。
**绝不自动**：保护清单命中、有实质差异（相似≠相同）、任何物理删除 / 改正文——一律请示。详见 `references/knowledge-network.md` §6。

## 6. 入库准入五关（本技能「入库校验」的实战升级版）

| 关卡 | 判定 | 未过处理 |
|------|------|---------|
| ①来源关 | 来源明确：本人产出/转发链接/会议音视频/巡检归集 | 无来源孤立文件→退回请示 |
| ②命名关 | [类型前缀]+有效标题 | 给改名建议，确认后修正 |
| ③内容关 | 非空、可提取、完整 | 登记状态"内容不全"，请示处置 |
| ④查重关 | 与索引库标题+摘要比对 | 拒收副本，指向已有条目 |
| ⑤价值关 | 工作参考/知识沉淀/证据留存至少一项 | 纯时效快照不入库 |

**三出口**：✅ 准入（打标→归位→登记）｜⚠️ 待确认（收件箱缓冲，补关重走）｜❌ 不入库（移独立「隔离区」暂存，说明依据，可复核翻案重回准入）。

## 7. 六环节闭环 + 两条回流线

```
①入库 → ②打标 → ③分类 → ④调用复核 → ⑤复盘改进 → ⑥标准迭代
 ↑                                                        │
 └────────────── 标准回流（⑥→①）←────────────────────────┘
        复核回流（④→②③）：调用/健康数据反向修正打标与归位
```

每环有质量闸门（见 SKILL.md 主流程）；末端数据必须回流修正前端，否则闭环退化成流水线。

## 8. 索引库 12 字段设计（多维表格模式）

名称｜文件类型｜主题分类｜知识类型｜状态｜生命周期｜优先级｜调用次数｜更新时间｜所在位置（「根目录/xxx」带前缀统一格式）｜链接（直跳原文）｜内容摘要（一句话价值+查重标注）。

> 关键枚举受控：主题分类按库主知识域定制；状态/生命周期/优先级建议 4~7 值受控。位置格式必须统一，防止多写入方漂移。

## 9. harness 验证（方案质量闸门）

本技能产出方案后，运行 `scripts/harness.py` 自动校验（H1 双链零死链 / H2 type 枚举 / H3 必填字段 / H4 密级 / H5 生命周期 / H6 落地脚本一致性 / H7 知识网络方案完整性 / H8 保护与清理授权声明），**全绿才交付**。详见 SKILL.md「harness 验证」章节。
