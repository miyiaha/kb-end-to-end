# 企业受控词表冷启动向导

> 帮助企业在 10 分钟内生成定制化的 L2/L3 受控词表，降低知识库治理的初始门槛。

## 使用场景

当用户为企业/团队搭建知识库，且需要定制受控词表时，按本向导引导。个人用户可直接跳过，使用默认的个人/通用模板。

## 冷启动 10 问

依次询问以下问题，根据回答生成定制化 L2/L3 词表：

### 基础信息（必填）

**Q1. 你的组织类型是？**
- 制造业（含 OEM/ODM/代工）
- 互联网/科技
- 咨询/专业服务
- 零售/电商
- 教育/科研
- 其他（请描述）

→ 用于匹配行业模板，作为起点。

**Q2. 你的一级部门有哪些？请列举**
- 示例回答：采购部、研发部、质量部、生产部、销售部、财务部
- 记录为 L3 产出部门的初始清单

**Q3. 你的主要业务线/产品线有哪些？**
- 示例回答：护肤品线、保健品线、功能食品线
- 记录为 L2 业务域的初始清单

### 治理细化（推荐）

**Q4. 不同部门之间会共享知识吗？哪些知识是跨部门共用的？**
- 示例回答：质量标准采购和质量部共用，合同模板采购和法务共用
- 用于确定 `category` 字段的子分类维度

**Q5. 你的知识来源主要有哪些？**
- 选项：内部产出 / 外部引入（法规、客户标准）/ 会议沉淀 / 项目交付 / 培训材料
- 用于填充 frontmatter 的 `source` 字段默认值

**Q6. 是否有现成的文件密级分类？**
- 选项：已有分级制度（请描述）/ 没有，使用默认 4 档 / 不确定
- 默认 4 档：公开 / 内部 / 受限 / 机密

### 调用与运维

**Q7. 知识库的主要使用者是谁？**
- 选项：仅自己 / 本部门 / 全公司 / 多组织
- 影响密级闸门的默认策略

**Q8. 你期望知识多久复审一次？**
- 选项：月度 / 季度 / 半年 / 年度 / 按需
- 用于填充 `valid_until` 的默认策略

**Q9. 是否有需要特别保护的敏感知识类型？**
- 示例回答：配方数据、客户名单、定价策略、合同条款
- 用于设置密级闸门的特殊规则

**Q10. 是否需要与现有系统对接？**
- 选项：Obsidian 独立使用 / 需与企业系统（ERP/OA/飞书等）对接 / 暂不确定
- 用于调整「调用路径」设计

## 输出格式

根据用户回答，输出定制化词表：

```markdown
# [组织名称] 受控词表 v1.0

## L2 业务域
| 编号 | 业务域 | 说明 |
|------|--------|------|
| BIZ-01 | xxx | xxx |
| BIZ-02 | xxx | xxx |

## L3 产出部门
| 编号 | 部门 | 上级部门 | 备注 |
|------|------|----------|------|
| DEP-01 | xxx | — | — |
| DEP-02 | xxx | — | — |

## L4 密级
（固定 4 档，无需定制）

## 特殊规则
（根据 Q9 回答生成）

## 维护约定
- 新增/撤销部门时：同步更新 L3
- 年度评审：检查 L2 是否需要新增/合并
- 法规变更时：触发复审
```

## 注意事项

1. **不要替用户做决定**：如果用户说不清楚，给建议选项让用户选，不要自行假设
2. **从行业模板出发**：先用模板填充默认值，让用户做增删，比从零开始高效
3. **标记为可调**：生成的词表标注「v1.0 - 可调」，后续随使用迭代
4. **个人用户简化**：如果用户是个人用途，只需 Q1+Q7，直接使用个人/通用模板
